## 4. 详细分析

### 4.1 HIGH：未授权目录遍历与信息泄露

**问题描述**

`project.rs` 中定义了三个 Tauri 命令：`scan_file_tree_cmd`、`git_status_cmd`、`analyze_deps_cmd`。它们接收任意 `path` 字符串，直接调用底层 scanner 函数读取目录结构、执行 `git status`、解析 `package.json` / `tsconfig.json`，**没有**与 `pick_project_folder` 选择的目录做一致性校验。

同一文件中，`scan_project` 与 `full_scan_project` 已经实现了正确的授权校验（比较 `req_canonical == allowed_canonical`），但这三个命令被遗漏。

**攻击路径**

1. 任意前端代码（或被 XSS 控制的页面）调用：
   ```ts
   invoke('scan_file_tree_cmd', { path: 'C:\\Users\\TargetUser\\Documents', maxDepth: 10 });
   invoke('git_status_cmd', { path: 'C:\\Users\\TargetUser\\some-repo' });
   invoke('analyze_deps_cmd', { path: 'C:\\Users\\TargetUser\\some-project' });
   ```
2. 后端无条件执行文件系统读取和 `git` 子命令，返回文件列表、Git 分支、变更文件、最近提交、依赖版本等敏感信息。

**影响范围**

- 本地用户其他目录的文件结构泄露
- 其他项目的 Git 提交历史、变更文件、依赖信息泄露
- 可被组合利用进行进一步社工或针对性攻击

**修复建议**

将这三个命令也纳入 `ProjectScanState` 授权管理：

1. 为 `scan_file_tree_cmd`、`git_status_cmd`、`analyze_deps_cmd` 的函数签名增加 `state: tauri::State<'_, ProjectScanState>`。
2. 在函数开头复用 `scan_project` 中的 canonical 路径校验逻辑，仅当传入路径等于最近一次 `pick_project_folder` 选择的路径时才允许执行。
3. 如果业务上确实需要读取子目录，应严格限制为 `allowed_path` 的子树（`req_canonical.starts_with(&allowed_canonical)`），而非任意路径。

### 4.2 MEDIUM：符号链接绕过敏感文件检查

**问题描述**

`read_image_file` 在读取图片时执行了以下检查：

1. `canonicalize` 获取真实路径，并调用 `is_in_user_scope` 校验是否位于用户主目录或临时目录。
2. 用 `pb.file_name()` 获取文件名，调用 `is_sensitive_file` 校验是否为敏感文件。
3. 用 `pb.extension()` 获取扩展名，校验图片格式。
4. **但 `fs::File::open(&pb)` 使用的是原始路径 `pb`，而不是 `canonical`。**

如果攻击者创建一个名为 `avatar.png` 的符号链接，指向 `C:\Users\User\.ssh\id_rsa`：

- `canonical` 为 `C:\Users\User\.ssh\id_rsa`
- `is_in_user_scope` 返回 true（在用户目录下）
- `pb.file_name()` 为 `avatar.png`，`is_sensitive_file("avatar.png")` 返回 false
- `pb.extension()` 为 `png`，通过格式校验
- `fs::File::open(&pb)` 会跟随符号链接，实际读取 `id_rsa` 内容

**影响范围**

- 在用户主目录/临时目录范围内，通过符号链接读取敏感文件内容（SSH 私钥、凭证文件、数据库文件等）。
- Windows 上创建符号链接默认需要管理员权限，但 Linux/macOS 上普通用户即可创建，跨平台风险不可忽视。

**修复建议**

1. 敏感文件检查应基于 `canonical` 路径的最终文件名和路径段，而非符号链接名。
2. 文件打开、扩展名校验、大小读取统一使用 `canonical` 路径，消除 TOCTOU 类不一致。
3. 可考虑在 `is_sensitive_file` 中同时检查路径 segment 是否包含 `.ssh`、`.aws` 等敏感目录名。

## 5. 已排除的风险项（说明理由）

| 风险项 | 结论 | 理由 |
|---|---|---|
| XSS | 未发现 | 全仓库未出现 `dangerouslySetInnerHTML` / `innerHTML` / `outerHTML` / `document.write` / `eval` / `new Function`；React 默认转义 |
| SQL 注入 | 未发现 | `sqlite.ts` 与 `vectorStore.ts` 全部使用参数化查询；`searchPromptHistory` 的 `LIKE` 模式先构造再作为参数传入，无拼接 |
| 命令注入 | 未发现 | Rust 侧仅有 `Command::new("git")` / `tasklist` / `kill`，参数为固定子命令或进程 ID；`sidecar.rs` 启动 `llama-server` 时参数为配置值，未通过 shell 拼接 |
| 不安全 YAML 反序列化 | 未发现 | 使用 `yaml.parse`（安全解析，不实例化任意类型），未使用 `yaml.load` |
| 硬编码密钥 | 未发现 | 搜索仅发现测试文件中的假 token；生产代码通过 keyring / sessionStorage 存储密钥 |
| API Key 泄露 | 未发现 | Tauri 侧使用 Windows Credential Manager；浏览器降级用 `sessionStorage`；`openai-adapter.ts` 对错误回显做脱敏处理 |
| SSRF | 低风险 | `validateBaseUrl` 已阻止私有 IPv4/IPv6 与除 localhost 外的 HTTP；注释已说明 DNS 重绑定需额外代理方案 |
| CSRF | 不适用 | 桌面应用无浏览器跨站请求场景 |
| 依赖项漏洞 | 未审计 | 本次为静态代码审计，未运行 `npm audit` / `cargo audit`；建议作为独立流程补充 |
