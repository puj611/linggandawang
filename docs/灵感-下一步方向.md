# 灵感 · 下一步方向

> **文档定位**：灵感大王项目战略方向决策文档，基于瓶颈分析确定下一阶段核心突破点。
> **版本**：v1.0
> **日期**：2026-07-24
> **状态**：复赛冲刺期（Phase 2）

---

## 一、现状一句话

**灵感大王完成了"灵感→提问→提示词"的单次闭环，但离"全生命周期伴随"还有三个断层：项目感知未打通、进度同步未联动、智能降级体验粗糙。**

---

## 二、三个核心断层

### 断层 1：项目感知 — 扫描器是地基

项目扫描器（M10）是阶段二所有后续功能的基础。当前状态：

- 前端壳 `ProjectScanDashboard.tsx` 已就绪
- Rust 端 `scanner.rs` 有文件遍历 + 敏感文件过滤
- **缺失**：`lib.rs` 中 `scan_project` / `full_scan_project` 命令的完整实现，依赖图分析、TODO 扫描未接入

**没有项目扫描器，后续的需求同步、进度感知、提示词去重全部无法启动。**

### 断层 2：进度同步 — 提示词无法"跟项目走"

需求同步器（M11）v0.3.0 已完成核心逻辑，但：

- 提示词生成时**未注入项目上下文**（技术栈、目录结构、Git 状态）
- 用户回答问题时**看不到项目当前进度**
- 生成的提示词**无法基于已完成任务去重**

### 断层 3：智能降级 — 离线体验断崖

本地 SLM（Phase B）和 RAG（Phase C）已集成，但：

- sidecar 进程管理不稳定（已有修复记录 fd8988d）
- 1-3B 模型中文质量与云端 LLM 差距大
- 无清晰的"有 LLM / 无 LLM / 本地 SLM"三档体验设计
- 用户一旦用过 LLM 增强版，离线模式体验降级明显

---

## 三、战略方向：三个选择

### 方向 A：补断层（稳健路线）— 推荐

**核心逻辑**：先打通项目感知→进度同步→提示词注入的完整链路，让产品从"单次工具"升级为"伴随助手"。

| 阶段 | 目标 | 关键产出 | 预估 |
|------|------|---------|------|
| **A1：扫描器闭环** | 项目上下文可自动注入提示词 | Rust 端完整实现 + 前端仪表盘联调 | 5d |
| **A2：上下文注入** | 提示词生成时自动携带项目信息 | PromptGenerator 改造 + 测试 | 3d |
| **A3：进度去重** | 已完成任务不再重复提问 | RequirementSyncer + Selector 联动 | 3d |
| **A4：体验打磨** | 三档降级体验清晰 | UI 引导 + 错误状态 + 离线提示 | 2d |

**优势**：功能完整度从 54% → 80%+，复赛评委能看到"全生命周期"的雏形
**风险**：Rust 开发量大，时间紧（22 个工作日）

### 方向 B：深打磨（体验路线）

**核心逻辑**：不追新功能，把现有功能做到极致——视觉、交互、稳定性、测试覆盖。

| 阶段 | 目标 | 关键产出 | 预估 |
|------|------|---------|------|
| **B1：测试补齐** | 覆盖率 ≥80% | 6 个 engine 模块单测 | 3d |
| **B2：视觉打磨** | 动效/过渡/空状态/错误状态 | CSS 动画 + 组件状态完善 | 3d |
| **B3：问题库扩充** | 45 → 80+ 条 | 新增 35 条覆盖更多场景 | 2d |
| **B4：稳定加固** | sidecar 进程管理 + LLM 降级 | 熔断器优化 + 重试策略 | 2d |

**优势**：工程质量上台阶，评委体验流畅
**风险**：功能断层仍在，"全生命周期"定位无法兑现

### 方向 C：抢窗口（速度路线）

**核心逻辑**：PromptPerfect 9 月关闭，抢先发布可用版本抢占市场。

| 阶段 | 目标 | 关键产出 | 预估 |
|------|------|---------|------|
| **C1：最小发布** | 可安装可体验 | 打包 + 安装指南 + 快速上手 | 1d |
| **C2：社区曝光** | GitHub stars + 反馈 | README 重写 + 演示 GIF + 社区发帖 | 2d |
| **C3：快速迭代** | 基于反馈高频更新 | 每周一个 patch | 持续 |

**优势**：抢占时间窗口，获取真实用户反馈
**风险**：功能不完整可能影响口碑

## 四、推荐路径：A + B 混合

**理由**：复赛评委既要看到功能完整度（方向 A），也要看到工程质量（方向 B）。两者不矛盾——测试补齐和视觉打磨可以穿插在功能开发中。

## 五、不做什么（裁剪清单）

为保证核心链路完整，以下功能明确推迟到赛后：

| 功能 | 推迟理由 |
|------|---------|
| 多轮迭代闭环（M14） | 依赖阶段二完整，工时不足 |
| 技术债感知（M15） | 锦上添花，非核心差异化 |
| 架构决策辅助（M16） | 低影响力 + 高实现难度 |
| 深色/浅色主题切换 | 基础体验，不影响核心价值 |
| 多语言界面 | 海外市场，非当前阶段重点 |
| 插件生态 | 长期规划，非复赛重点 |

## 六、成功标准

### 复赛提交最低标准（Must Have）

- [ ] 项目扫描器可用：输入项目路径 → 输出文件结构 + 技术栈 + Git 状态
- [ ] 提示词自动注入项目上下文：生成的提示词包含项目信息段
- [ ] 核心闭环稳定：唤起 → 提问 → 生成 → 复制，全流程无报错
- [ ] 测试覆盖率 ≥75%
- [ ] 安装包可正常安装运行

### 复赛提交加分标准（Nice to Have）

- [ ] 进度去重：已完成任务不再重复提问
- [ ] 三档降级体验清晰
- [ ] 问题库 60+ 条
- [ ] 演示视频 + 复赛帖完整
